## 2. 已知问题：根因与设计

### 2.1 Split View 空白

**现象**：打开 Split View 后右侧是空白编辑器，没有当前文档内容。

**根因候选**：
- 右侧是独立 `TATSynEdit`，只在 toggle、`EditorChanged` 定时器和 `PageChanged` 时复制文本。
- 文件加载、标签创建、会话恢复、页面切换的部分路径不会触发刷新；`PageChanged` 在 `FRestoring` 时直接退出。
- 只复制 `Text`，没有同步字体、主题、lexer；白色/透明文本也会表现为“空白”。
- 右侧面板与主窗口置顶状态冲突时可能被遮挡。

**设计**：
- 定义唯一入口 `RefreshDocumentMap`。以下事件都调用：
  - `ToggleSplitView`
  - `PageChanged`（包括恢复完成后）
  - `CreateTab`
  - `LoadFileIntoTab` / `ReloadTab` / 会话恢复结束
  - 编辑器 `OnChange`（去抖）
- `RefreshDocumentMap` 检查 `ActiveTab`、文本长度、可见性；复制文本后恢复 `LineTop`。
- 同步字体、编辑器配色、滚动条、只读状态；显示行号/标尺跟随主题。
- 明确文案：`Document map (read-only)`，不是可编辑的分屏。若要真正的可编辑双视图，另立任务，不在本轮混入。

**验收**：
1. 打开含 100 行文本的文件，按 F8。
2. 右侧显示同样 100 行，字体、背景、前景色与主编辑器一致。
3. 在主编辑器输入/删除/滚动，250ms 内右侧内容更新，滚动位置不被强制重置。
4. 切换标签、打开文件、恢复会话后不空白。
5. 截图对比左右文本行数与背景色；自动测试至少覆盖“打开文件后 F8”和“F8 后打开文件”。

### 2.2 查找框无法输入、回车不查找、找到后不跳转

**根因**：
- 查找框曾使用 `TTyComboBox` 的默认 `csDropDownList`（只读）。
- 查找对话框可能被置顶主窗口遮挡，表现为黑/白空窗。
- `ShowFind` 只 `SetFocus`，没有处理 Enter；`DoFindNext` 依赖 finder 更新 caret，对话框遮挡时用户看不到结果。

**设计**：
- 保留 `TTyComboBox`，明确设置：
  - `Style := csDropDown`
  - `ReadOnly := False`
  - `Items` 来自查找历史
  - `AutoComplete`/前缀补全行为按 TyControls 文档确认
- 对话框属于主窗口的 owned form；主窗口置顶时，查找/替换/在文件中查找等对话窗口也必须置顶或使用 PopupParent，不能被主窗口盖住。
- 打开时：
  - `FFindEdit.SetFocus`
  - `SelectAll`
  - 若编辑器有选中文本/当前词，预填并全选
- 键盘：
  - `Enter`：Find Next
  - `Shift+Enter`：Find Previous
  - `Escape`：关闭对话框
  - `F3`/`Shift+F3`：主窗口继续查找
  - `Alt+C` 等助记符不与输入冲突
- 找到后：
  - `DoGotoPos(MatchEdPos, MatchEdEnd)` 确保滚动/选中
  - 状态栏/结果标签显示行、列
  - 查找窗口保持焦点（用户可连续 Enter），但匹配文本必须在编辑器中可见
- 替换：Enter 行为单独定义，避免误替换；`Replace` 按钮与快捷键明确。

**验收**：
1. Ctrl+F 后查找框有焦点，可直接输入，文本可见。
2. 输入关键字按 Enter，编辑区滚动到匹配处并选中。
3. Shift+Enter 反向查找；Escape 关闭；F3 继续。
4. 主窗口置顶时，查找窗口仍可见且可输入。
5. 历史下拉可选择旧关键字。

### 2.3 窗口置顶在 Windows 无效

**根因候选**：
- LCL `FormStyle := fsStayOnTop` 在 Windows 上可能被 TyForm 的窗口重建/主题应用覆盖。
- 只设置了主窗口，子对话框没有 owned/topmost 关系；主窗口置顶后遮住查找等窗口。
- 状态没有持久化或在启动后丢失。

**设计**：
- 统一 `ApplyAlwaysOnTop`：
  - LCL `FormStyle` 与 Windows 原生 `SetWindowPos(HWND_TOPMOST/HWND_NOTOPMOST)` 双路径。
  - 在窗体 Show 后应用，而不是只在构造时设置。
  - 主窗口置顶时，Owned 对话框同样置顶；对话框关闭后恢复普通。
  - `settings.json` 保存并启动恢复。
- 不依赖窗口管理器猜测；Windows 用 Win32 API，Linux 可用 LCL + 验证 `_NET_WM_STATE_ABOVE`。

**验收**：
1. Windows 上切换置顶，`WS_EX_TOPMOST` 存在/移除。
2. 置顶后主窗口覆盖其他应用；查找窗口仍可见、可操作。
3. 重启后状态保持。
4. Linux 同样验证 `_NET_WM_STATE_ABOVE`。

### 2.4 Ruler 不跟随编辑器主题

**根因**：`TATEditorColors` 有 `RulerBG`/`RulerFont`，但 `ApplyPalette` 只设置正文、边栏、选择等，从未设置标尺颜色。

**设计**：
- 在 `TEditorPalette` 增加 `RulerBG`、`RulerFont`，默认分别取 `GutterBG`、`GutterText`。
- 内置配色方案、JSON 导入导出、自定义配色编辑器全部包含这两个字段。
- `ApplyPalette` 设置 `AEditor.Colors.RulerBG/RulerFont`。
- 标尺的字体尺寸/刻度逻辑保持不变，只改颜色。

**验收**：浅色/深色、8 套内置方案、自定义方案下，标尺背景和文字均与编辑器主题一致；截图/像素断言。

### 2.5 配色编辑器使用手输 RGB

**设计**：
- 使用 TyControls 已有控件：
  - `TTyColorButton`（色块 + `SelectedColor` + `OnColorChange`）
  - 点击打开 `TTyColorDialog`（`LCLColor`/`Color`）
- 颜色列表改为“角色名 + 色块 + 只读 `#RRGGBB` 文本”；不再要求用户输入十六进制。
- 选择角色后点色块打开颜色对话框；实时预览；Cancel 回滚，OK 应用。
- 保留键盘可访问性：Tab 到色块、Enter/Space 打开。

**验收**：
1. 打开编辑器，每个角色显示色块和当前颜色。
2. 点击色块弹出 TyControls 颜色对话框；选色后预览变化。
3. Cancel 不改文件；OK 保存并在重启后保留。
4. 不再存在必须手动输入 RGB 的输入框。

## 4. 中文本地化流程

已扫描 `Tr('...')`：应用自有 key 184 个，当前 JSON 覆盖不足，缺 43 个直接 key。未计动态拼接、TyControls 内置文案和错误消息。

执行：
1. 脚本提取所有 `Tr` key，与 `tyeditor.zh_CN.json` 做差集。
2. 先补齐 43 个缺失 key，再检查动态 `Format(Tr(...))` 和异常消息。
3. TyControls 的 `tycontrols.zh_CN.po` 同步检查。
4. 运行中文界面截图/OCR 冒烟，确保对话框、按钮、空状态、错误提示没有英文。
5. 增加 CI 检查：缺 key 直接失败，防止回退。

## 5. UX 统一规范

- 对话框打开时焦点落在首要输入框；`Enter` 执行主操作，`Escape` 关闭。
- 普通成功操作不弹模态框；用状态栏/短暂提示反馈。
- 破坏性操作才确认；确认框按钮文案必须具体。
- 子对话框不得被主窗口置顶状态遮挡。
- 所有可见控件必须在主题切换时同步换色，包括标尺、滚动条、文档地图。
- 错误信息说明“发生了什么 + 用户能做什么”，不要只显示异常类名。
- 快捷键冲突、Tab 顺序、默认按钮、最小窗口尺寸纳入每条验收。
