# TyEditor 阶段 2 实施计划

状态：核心功能已实现；自动补全、鼠标宏录制是计划中明确的可选项，默认关闭，未列入阶段 2 强制出口。阶段 2 的目标是把 Notepad++ 的日常高频能力补齐到“可以替代默认编辑器”的程度，而不是追求功能数量。

## 2. 里程碑

### 2.1 编码自动检测与 BOM 管理（P0，已实现基础）

问题：当前非 UTF-8 文件可能先按 ANSI/UTF-8 打开，用户必须手动重载；这直接破坏“文本编辑器不能忽略行末空格/字符”的可信度。

进度：`DetectFileEncoding` 已覆盖 BOM、UTF-8、UTF-16 LE/BE、GBK、Big5、Shift-JIS、EUC-KR，并接入打开/重载/会话恢复；`tests/testencoding` 覆盖样本矩阵。剩余：每文件编码历史与低置信度 UI。

实施：

- 新增 `uencoding` 检测入口：BOM 优先，UTF-8 合法性校验，随后对 GBK、Big5、Shift-JIS、EUC-KR 做候选评分。GB18030 四字节序列需要额外的编码表，暂列后续。
- 检测结果带置信度；低置信度不自动改编码，保持用户可手动选择。
- 编码菜单增加：最近使用编码、BOM 添加/移除、按当前编码重新载入、失败时保留原内容。
- `usettings` 增加 `encoding_detect`、`encoding_history`；会话保存每个文件的编码，但不把自动检测结果写回文件。
- 测试样本覆盖：ASCII、UTF-8 无 BOM、UTF-8 BOM、GBK、GB18030、Big5、Shift-JIS、EUC-KR、UTF-16 LE/BE、混合换行。

验收：

- 打开上述样本，除低置信度样本外状态栏编码正确、无乱码。
- 用户显式选择编码后，保存/重载不得被自动检测覆盖。
- BOM 操作可逆，保存后外部工具可验证字节。

### 2.2 会话、快照与崩溃恢复（P0，已实现基础）

问题：目前备份只有当前会话使用的一份文本，缺少崩溃提示和可配置保留策略；异常退出后用户不知道是否存在可恢复内容。

进度：`running.marker`、异常退出提示、恢复设置开关和正常关闭清理已接入；已手工验证 kill 后重启恢复。剩余：可配置备份目录/保留数量与快照历史。

实施：

- `session.json` 使用临时文件 + rename 原子写入；写入失败不破坏旧会话。
- 快照目录、保留数量、自动快照间隔全部进入设置；清理策略按会话/数量执行。
- 启动时写入 `running.marker`，正常退出删除；发现残留标记时显示“上次未正常退出，是否恢复”对话框。
- 统一关闭标签/全部关闭/退出程序的保存策略，确保“不保存也不阻塞关闭”的既有语义不变。
- 备份文件命名带会话 ID 与时间戳，恢复对话框显示文件路径、修改时间、标签数。

验收：

- 强制 kill 进程后重启，能恢复最近快照，且不会覆盖用户已保存的文件。
- 原子写入模拟失败时，旧 `session.json` 仍可读取。
- 备份数量达到上限后只删除最旧快照。
- 关闭最后一个标签仍按现有逻辑退出，不弹多余的保存提示。

### 2.3 在文件中查找异步化（P0）

问题：`ufindfiles.pas` 当前在 UI 线程递归扫描并读取文件，大目录会卡住窗口；没有取消和进度反馈。

实施：

- 把文件枚举、二进制判断、读取/匹配放入工作线程；结果和进度通过线程安全队列回传主线程。
- UI 增加进度条、当前文件、已扫描/命中计数、Stop 按钮；关闭对话框或再次搜索时安全取消。
- 支持包含/排除目录与通配符；保留当前“先确认再替换”的保护。
- 结果面板支持导出为文本/JSON，双击结果继续跳转。
- 替换仍要求主线程执行文件写入；替换前校验文件未被外部修改。

验收：

- 扫描大型目录时窗口可拖动、可取消，取消后不再追加过期结果。
- 关闭对话框不会留下线程或访问已释放控件。
- 结果数量与同步版本一致；导出内容可被重新导入/阅读。

### 2.4 标签页与导航（P1）

实施：

- 标签右键菜单：关闭、关闭其他、关闭右侧、复制路径、在文件管理器中显示、固定/取消固定。
- 固定标签不参与“关闭其他/关闭全部”，状态写入会话。
- 标签溢出菜单；最近关闭标签栈，支持 Ctrl+Shift+T 重开。
- 标签右键菜单与现有 TyControls `TTyTabStrip` 事件对齐，避免重复删除页面。

验收：

- 固定标签在会话恢复后仍固定；关闭其他不会关闭固定标签。
- 重开已关闭标签恢复路径、编码、光标；未保存内容按备份策略处理。
- 关闭中间标签不会误关下一个标签（回归现有修复）。

### 2.5 编辑与查找体验（P1）

实施：

- 缩进参考线、括号匹配/跳转、可选自动补全；自动补全默认关闭。
- 每语言 Tab 宽度/空格/自动缩进覆盖；语言切换时应用但不修改文件内容。
- 查找历史、正则替换预览、选区查找、结果面板内查找。
- 补齐行操作菜单项的可发现性和快捷键；多光标操作继续走显式命令，不改变默认单光标。

验收：

- 默认文本模式不引入自动缩进/自动括号/虚拟空格回归。
- 每语言设置只影响对应 lexer 的文档；无 lexer 时使用全局设置。
- 替换预览取消后文件字节不变。

### 2.6 宏与书签（P2）

实施：

- 宏管理窗口：列表、重命名、删除、导入/导出、绑定快捷键。
- 可选录制鼠标点击/滚动，默认关闭；录制内容与现有 JSON 格式兼容。
- 书签列表：按文件分组、跳转、删除、颜色/分组；书签状态继续写入会话。

验收：

- 旧宏文件可加载；宏回放不破坏撤销栈。
- 书签列表跳转后光标/滚动位置正确；重启后颜色和分组保留。

### 2.7 界面与系统集成（P2）

实施：

- 分屏/双视图与文档地图；优先做只读文档地图，避免和 ATSynEdit 光标同步产生双份状态。
- 配色方案编辑器/导入导出；保持现有 8 套内置方案兼容。
- 单实例（第二实例把文件转交第一实例）、文件关联、Windows 安装包。
- 只读文件、网络路径、长路径的打开/保存错误路径测试。

验收：

- 分屏两侧独立光标/滚动，不共享编辑缓冲区导致互相覆盖。
- 第二实例转交文件后自身退出，第一实例新开标签。
- 安装包卸载不删除用户设置/备份。

## 3. 实施结果

每项验收证据见 [PHASE2_TASKS.md](PHASE2_TASKS.md)。自动补全和鼠标宏录制是计划中的可选项，默认关闭；阶段 2 强制出口为 P0/P1 项。

## 4. 实施顺序

1. **Wave A（数据安全）**：2.1 编码检测 + 2.2 会话/崩溃恢复；先补自动化测试。
2. **Wave B（大目录可用性）**：2.3 异步查找 + 2.5 查找历史/预览。
3. **Wave C（日常操作）**：2.4 标签菜单/重开 + 2.5 编辑辅助。
4. **Wave D（增强）**：2.6 宏/书签 + 2.7 分屏/系统集成。

每个 Wave 结束都必须同时满足：Linux Qt6 冒烟通过、Windows i386 构建通过、macOS universal 构建通过、文档/翻译同步。

## 5. 测试与出口标准

- 新增单元测试：编码检测样本矩阵（`tests/testencoding`）、会话 JSON 往返/原子写、备份清理、查找取消。
- GUI 手工验收追加到 `docs/TESTING.md`：崩溃恢复、异步查找取消、标签固定/重开、分屏。
- 性能基线：10 万行文件打开/滚动可交互；在 1 万个文件的目录中查找可取消。
- 阶段 2 完成标准：上表所有 P0/P1 项验收通过；无已知数据丢失问题；三种目标平台构建成功；README/ROADMAP/TESTING 与实现一致。

## 6. 风险与约束

- 编码启发式必然有误判：必须保留手动覆盖和“按当前编码重载”，低置信度不自动切换。
- LCL 控件只能主线程访问：搜索线程不得直接更新 UI，统一队列回传。
- TyControls 标签/标题栏行为以现有版本为准：先读 `docs/controls/` 与示例，避免复制页面删除逻辑。
- 会话恢复优先保证“不丢内容”，宁可恢复多余标签，也不静默丢弃未保存文本。
